# خادم AMOS Backend

هذا الخادم هو الطبقة الخلفية (Backend) لنظام AMOS — يوفر:
- قاعدة بيانات مركزية دائمة (PostgreSQL عبر Supabase — مجانية ولا تُمسح أبداً) للموظفين وسجلات الحضور
- مزامنة تلقائية مع جهاز البصمة/الوجه عبر الشبكة
- إرسال تقارير حضور تلقائية (يومي/أسبوعي/شهري) بالإيميل
- واجهة API يمكن لتطبيق AMOS (الواجهة الأمامية) الاتصال بها لاحقاً بدل التخزين المحلي

---

## 1. المتطلبات

- **Node.js** إصدار 18 أو أحدث — حمّله من [nodejs.org](https://nodejs.org) (فقط لو حابب تجرّبه محلياً قبل النشر)
- حساب **Supabase** مجاني (قاعدة البيانات الدائمة)
- حساب **Render** مجاني (استضافة الخادم)
- حساب **GitHub** (لربط المشروع بـ Render)
- (اختياري) حساب **UptimeRobot** مجاني (لمنع الخادم من "النوم")
- (اختياري) جهاز بصمة متصل بنفس الشبكة، إذا تبي المزامنة التلقائية

---

## 2. إنشاء قاعدة البيانات (Supabase) — أول خطوة

1. روح لـ **supabase.com** → **Start your project** → سجّل دخول بـ GitHub
2. اضغط **New Project**
3. اختر اسم للمشروع + كلمة مرور لقاعدة البيانات (احفظها، بتحتاجها)
4. اختر أقرب منطقة جغرافية (Region) وانتظر دقيقة لين ينشئ المشروع
5. بعد ما يخلص، روح لـ **Project Settings** (⚙️) → **Database**
6. تحت **Connection string**، اختر تبويب **URI** وانسخ الرابط الكامل
7. استبدل `[YOUR-PASSWORD]` بكلمة المرور اللي حفظتها بالخطوة 3

هذا الرابط هو قيمة `DATABASE_URL` اللي بتحتاجها بالخطوة الجاية.

---

## 3. تشغيل الخادم (محلياً للتجربة، أو مباشرة على Render)

```bash
# 1. ادخل مجلد المشروع
cd amos-backend

# 2. ثبّت الحزم المطلوبة
npm install

# 3. انسخ ملف الإعدادات وعدّله
cp .env.example .env
```

افتح ملف `.env` وعدّل القيم التالية:

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | رابط Supabase اللي نسخته بالخطوة السابقة |
| `DEVICE_IP` | عنوان IP لجهاز البصمة (تجده من قائمة MENU > Comm بالجهاز) |
| `DEVICE_ENABLED` | اجعلها `true` فقط بعد ما تتأكد من IP الجهاز، وإلا خلها `false` للتجربة بدون جهاز |
| `SMTP_USER` / `SMTP_PASS` | بيانات إيميل الإرسال (راجع القسم 5 أدناه لإعداد Gmail) |
| `REPORT_RECIPIENT` | الإيميل اللي بتوصله التقارير التلقائية |

```bash
# 4. شغّل الخادم (للتجربة المحلية فقط)
npm start
```

لو كل شي تمام بتشوف رسالة:
```
✅ AMOS Backend يعمل الآن على المنفذ 4000
```

## 4. نشر الخادم مجاناً على الإنترنت (Render)

1. ارفع مجلد `amos-backend` على مستودع GitHub جديد (نفس طريقة السحب والإفلات في github.com — بدون أوامر Git)
2. روح لـ **render.com** → سجّل دخول بـ GitHub
3. اضغط **New** → **Web Service**
4. اختر المستودع اللي رفعته
5. اضبط:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
6. تحت **Environment Variables**، أضف نفس القيم اللي بملف `.env` عندك (خصوصاً `DATABASE_URL`)
7. اضغط **Create Web Service** — انتظر دقيقتين لين يخلص النشر
8. Render بيعطيك رابط عام مثل: `https://amos-backend.onrender.com`

### منع الخادم من "النوم" (مهم لأن الخطة مجانية)
خدمات Render المجانية تنام بعد 15 دقيقة خمول. لتفادي هذا:
1. روح لـ **uptimerobot.com** → أنشئ حساب مجاني
2. أضف **New Monitor** → نوع **HTTP(s)**
3. الرابط: `https://amos-backend.onrender.com/api/health`
4. فترة الفحص: كل 5 دقائق

هذا يخلي UptimeRobot "يوقظ" خادمك تلقائياً قبل ما ينام، فيبقى شغّال بشكل شبه دائم مجاناً.

> **ملاحظة صادقة:** حتى مع هذا الحل، قد يحصل أحياناً تأخير بسيط (10-30 ثانية) في أول طلب بعد فترة خمول طويلة. البيانات نفسها آمنة 100% لأنها في Supabase (منفصلة عن الخادم)، فحتى لو الخادم أعاد التشغيل، البيانات ما تتأثر أبداً.

## 5. ربط جهاز البصمة

1. من قائمة الجهاز: **MENU > Comm (الاتصال)** — تأكد إن الجهاز على نفس شبكة الكمبيوتر اللي يشغّل الخادم (ملاحظة: هذا يتطلب تشغيل الخادم محلياً على نفس شبكة الجهاز، أو عبر VPN، لأن Render لا يقدر يوصل لشبكتك الداخلية مباشرة)
2. دوّن عنوان IP واكتبه في `.env` (`DEVICE_IP`)
3. لكل موظف، تحتاج تربط "رقم الملف" في AMOS برقم المستخدم داخل الجهاز نفسه (`device_uid`) — أضفه عند إنشاء أو تعديل الموظف عبر:
   ```
   POST /api/employees
   { "id": "M04210", "name": "...", "role": "...", "device_uid": "17" }
   ```
4. فعّل `DEVICE_ENABLED=true` في `.env` وأعد تشغيل الخادم

> **ملاحظة:** إذا جهازك لا يستخدم بروتوكول ZKTeco القياسي (المكتبة المستخدمة هنا هي `node-zklib`)، قد تحتاج SDK مختلف. جرّب أولاً بـ `DEVICE_ENABLED=true` وشوف رسائل الخطأ في اللوقز (Logs بلوحة Render، أو الطرفية لو تجرّب محلياً) — إذا فشل الاتصال، أرسل لي رسالة الخطأ ونشوف الحل المناسب لموديل جهازك بالتحديد.

للاختبار الفوري بدون انتظار الجدولة (استبدل الرابط برابطك الفعلي — محلي أو على Render):
```bash
curl -X POST https://your-app.onrender.com/api/device/sync-now
```

## 6. إعداد إرسال الإيميل (مثال Gmail)

1. فعّل **التحقق بخطوتين** في حساب Google الخاص بالإرسال
2. اذهب إلى: [myaccount.google.com/apppasswords](https://myaccount.google.com/apppasswords)
3. أنشئ "App Password" جديدة (اختر "Mail" كنوع التطبيق)
4. انسخ كلمة المرور المولّدة (16 حرف) وضعها في `.env` (ومتغيرات البيئة بـ Render):
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=your-email@gmail.com
   SMTP_PASS=xxxx xxxx xxxx xxxx
   ```

للاختبار الفوري بدون انتظار الجدولة:
```bash
curl -X POST https://your-app.onrender.com/api/reports/send-now -H "Content-Type: application/json" -d "{\"period\":\"daily\"}"
```

## 7. جدول أوقات التقارير التلقائية (Cron)

القيم الافتراضية في `.env`:

| التقرير | الوقت الافتراضي |
|---|---|
| يومي | كل يوم الساعة 6:00 مساءً |
| أسبوعي | كل أحد الساعة 6:00 مساءً |
| شهري | آخر يوم في الشهر الساعة 6:00 مساءً |

لتغيير الأوقات، عدّل قيم `DAILY_REPORT_CRON` / `WEEKLY_REPORT_CRON` / `MONTHLY_REPORT_CRON` في `.env` — استخدم أي أداة "cron expression generator" مجانية على الإنترنت لتوليد الصيغة الصحيحة بسهولة.

> **تذكير:** الجدولة تشتغل فقط وقت ما يكون الخادم "مستيقظ". مع UptimeRobot (القسم 4)، الخادم يبقى مستيقظ تقريباً دائماً، فالجدولة تشتغل بموثوقية عالية جداً.

## 8. نقاط الـ API المتاحة

| Method | المسار | الوصف |
|---|---|---|
| GET | `/api/health` | فحص أن الخادم يعمل |
| GET | `/api/employees` | كل الموظفين |
| POST | `/api/employees` | إضافة موظف |
| PUT | `/api/employees/:id` | تعديل موظف |
| PATCH | `/api/employees/:id/reset` | إعادة تعيين حالة موظف |
| DELETE | `/api/employees/:id` | حذف موظف |
| POST | `/api/attendance/checkin` | تسجيل حضور يدوي |
| POST | `/api/attendance/checkout` | تسجيل انصراف يدوي |
| GET | `/api/attendance?period=daily` | سجلات فترة معيّنة |
| DELETE | `/api/attendance?period=daily` | حذف سجلات فترة معيّنة |
| POST | `/api/reports/send-now` | إرسال تقرير فوري (اختبار) |
| POST | `/api/device/sync-now` | مزامنة فورية مع الجهاز (اختبار) |

---

## 9. الخطوة التالية: ربط واجهة AMOS الأمامية بهذا الخادم

حالياً واجهة AMOS (ملف الـ HTML) تخزن البيانات محلياً في المتصفح. الخطوة التالية الطبيعية هي تعديلها لتتصل بهذا الخادم عبر نفس نقاط الـ API أعلاه (برابط Render بدل localhost) — إذا تحب، أجهّز لك هذا التعديل في الخطوة القادمة.

---

## 10. بديل: تشغيل دائم على سيرفر خاص (VPS)

لو يوماً ما قررت تنتقل من Render لسيرفر خاص بيك (مثل DigitalOcean أو Hetzner)، تقدر تشغّل الخادم بشكل دائم باستخدام **PM2**:

```bash
npm install -g pm2
pm2 start server.js --name amos-backend
pm2 save
pm2 startup
```

هذا يضمن أن الخادم يعمل تلقائياً حتى بعد إعادة تشغيل الجهاز. (ملاحظة: هذا غير مطلوب مع Render، لأن المنصة تدير تشغيل العملية نيابة عنك تلقائياً).
